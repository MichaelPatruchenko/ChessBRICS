# Шахматы БРИКС

Русскоязычный игровой зал для классических шахмат и шахмат БРИКС. Играйте по ссылке, через открытое лобби, на одном экране или с ботами. На доске подсвечиваются доступные ходы, последнее перемещение и угроза королю. В партии есть часы с добавкой, превращение пешки, журнал ходов, сдача и итоговый результат.

## Запуск

В этой папке выполните `npm start` с Node.js 22 или новее. Устанавливать npm-пакеты не нужно. Откройте [localhost:3000](http://localhost:3000).

Надпись «Разработано при поддержке» с логотипом компании включена по умолчанию. Чтобы скрыть её, установите `CHESSBRICS_SUPPORT_CREDIT=0` в `.env`. Для запуска через Node перезапустите сервис, для Docker выполните `docker compose up -d`.

Сервис поставляется в одном Docker-контейнере. По аналогии с SecretSanta интерфейс и сервер поставляются вместе. Фигуры — локальные SVG, а интерфейс загружается без CDN. Docker хранит комнаты в именованном томе. При запуске через Node данные сохраняются в папке `data`. Путь можно переопределить через `DATA_DIR`, адрес прослушивания через `HOST`, порт через `PORT`.

Для игры в локальной сети открывайте сервис по сетевому адресу сервера до создания комнаты. Ссылка, созданная через localhost, доступна только на той же машине. Для доступа из интернета используйте публичный HTTPS-адрес с обратным прокси к порту 3000. При запуске за прокси на той же машине задайте `CHESSBRICS_BIND=127.0.0.1` для Compose. Развёртывание рассчитано на один процесс с постоянным томом данных.

## Как сыграть

1. Выберите вариант, введите имя, задайте минуты и добавку, создайте комнату.
2. Отправьте ссылку одному сопернику в классике или БРИКС 1×1, либо троим в БРИКС 2×2. Партия начинается, когда все места заняты.
3. Чтобы вернуться в партию, откройте ту же ссылку в том же профиле браузера. Браузер хранит ключ места. С открытой ссылкой можно смотреть заполненную комнату. Для проверки на одной машине откройте отдельный профиль браузера для каждого игрока.
4. Выберите фигуру и подсвеченную клетку. Для рокировки в классике выберите клетку назначения короля, в БРИКС — доступную союзную фигуру. Клавиши со стрелками перемещают фокус по доске, Enter выбирает клетку.

## Принятые трактовки

Расстановка соответствует рис. 2. Красные и зелёные делят короля на e1, синие и оранжевые — короля на e10. Каждый управляет фигурами своего цвета. Фигура БРИКС прыгает на границу квадрата 7×7 по рис. 1. Рокировка — обмен нетронутого короля с любой нетронутой фигурой своей команды на той же горизонтали, кроме пешки. Промежуточные клетки могут быть заняты. Партия БРИКС завершается взятием короля. Угроза королю не ограничивает обычные ходы. Если у текущего цвета нет допустимых ходов, объявляется ничья. Сдача или истечение времени у цвета завершает партию для всей команды.

В БРИКС 1×1 та же расстановка на доске 10×10. Красные управляют всеми 20 фигурами снизу, оранжевые — всеми 20 фигурами сверху. Игроки ходят по очереди. У каждого свои часы.

Справка в игре описывает правила выбранного варианта. Завершённая онлайн-партия доступна по ссылке комнаты. Перечень реализованных возможностей и оставшихся разделов приведён в [сверке с концепцией](FEATURES.md).

## Развёртывание в Docker

На сервере нужны запущенный Docker Engine и Docker Compose v2. Для первой сборки нужен доступ к реестру Docker за базовым образом Node. На Windows нужен Docker Desktop в режиме Linux-контейнеров.

| Действие | Linux | Windows PowerShell |
| --- | --- | --- |
| Собрать и запустить | `bash ./deploy.sh` | `.\deploy.ps1` |
| Пересобрать и обновить | `bash ./deploy.sh update` | `.\deploy.ps1 update` |
| Проверить состояние | `bash ./deploy.sh status` | `.\deploy.ps1 status` |
| Посмотреть журнал | `bash ./deploy.sh logs` | `.\deploy.ps1 logs` |

Оба скрипта поддерживают `start`, `stop` и `restart`. При запуске скрипт ждёт ответа точки готовности `/healthz`, а при ошибке показывает журнал контейнера. Партии остаются в томе Compose при обновлении и остановке. Для своего порта или IP задайте `CHESSBRICS_PORT` и `CHESSBRICS_BIND` в окружении или в локальном файле `.env`. По умолчанию сервис слушает порт 3000 на всех интерфейсах.

Для проверки через браузер из папки проекта выполните:

```sh
python -m pip install -r tests/requirements.txt
python -m playwright install chromium
python tests/browser.py --base http://127.0.0.1:3000
```

Тест открывает четыре независимых сеанса, проверяет журнал, обновление позиции, возврат в комнату и тренировку на мобильном экране. Параметр `--restart-project` перезапускает указанное тестовое развёртывание Compose посреди партии. Используйте его только с выделенным тестовым проектом.

## Классика, БРИКС и боты

Выберите вариант перед созданием комнаты или тренировкой. Классика рассчитана на двух игроков и доску 8×8. БРИКС 1×1 и 2×2 используют доску 10×10. Игра на одном экране передаёт ход следующему цвету. Открытые комнаты появляются в лобби, если создатель явно включил показ. Можно скачать PGN классической партии или JSON партии БРИКС. После завершения партии стрелки журнала показывают предыдущие позиции.

В БРИКС победа наступает при взятии короля. Пешка на последней горизонтали может превратиться в БРИКС, ферзя, ладью, слона или коня. В классике шах ограничивает ходы, партия заканчивается матом или одним из условий ничьей.

Алгоритмические боты работают в браузере и доступны на трёх уровнях. Лёгкий выбирает допустимый ход случайно, средний оценивает результат своего хода, сильный оценивает ответы соперника. В БРИКС уровень «Сильный» использует точную таблицу позиций с двумя королями и дебютную книгу. В дебюте он начинает с рассчитанного хода и пытается углубить поиск. Для остальных позиций работает альфа-бета-поиск до пяти полуходов с лимитом 150 000 узлов на ход.

### Stockfish

Установите [Stockfish](https://official-stockfish.github.io/docs/stockfish-wiki/Download-and-usage.html) и укажите имя исполняемого файла из `PATH` или абсолютный путь в `CHESSBRICS_STOCKFISH_PATH`. После перезапуска в настройках классической тренировки появится Stockfish, и кнопка «Предложить ход» будет запрашивать у него ход и оценку. При недоступности внешнего движка приложение использует локальный алгоритм.

Для Docker путь должен указывать на исполняемый файл **внутри контейнера**. Его можно подключить через том только для чтения в локальном Compose override. Бинарник и его зависимости должны подходить для Linux и базового образа Alpine.

Официальный Stockfish работает с классической доской. Fairy-Stockfish умеет работать с большими досками и нестандартными фигурами, но для БРИКС 1×1 понадобятся изменения в генераторе ходов для рокировки-обмена и первого хода пешки до четырёх клеток. БРИКС 2×2 дополнительно требует поддержки очереди четырёх цветов. Оба режима используют движок ChessBRICS. [Документация Stockfish](https://official-stockfish.github.io/docs/stockfish-wiki/Stockfish-FAQ.html), [правила Fairy-Stockfish](https://github.com/fairy-stockfish/Fairy-Stockfish/blob/master/src/variant.h), [цвета Fairy-Stockfish](https://github.com/fairy-stockfish/Fairy-Stockfish/blob/master/src/types.h).

### LLM через API и наставник

Скопируйте `.env.example` в `.env` и заполните поля:

- `CHESSBRICS_LLM_URL` — полный URL совместимого endpoint Chat Completions.
- `CHESSBRICS_LLM_MODEL` — имя модели у провайдера.
- `CHESSBRICS_LLM_KEY` — API-ключ, если провайдер требует Bearer-токен.

Перезапустите приложение или выполните скрипт обновления Docker. В списке уровней появится «LLM через API». Игра идёт в серверной комнате. Сервер отправляет провайдеру позицию, очередь хода и список легальных ходов. Имена игроков и ключи мест остаются на сервере. В браузер передаётся только признак доступности LLM. При ошибке, тайм-ауте в 8 секунд, недопустимом ответе или исчерпании лимита ход выбирает алгоритмический бот. Для всего процесса действует лимит до 12 запросов в минуту и до двух одновременно.

Для локальной Gemma или Qwen в формате GGUF запустите `llama-server` с именем модели, совпадающим с настройкой ChessBRICS. Пример для запуска обоих сервисов на одной машине. [Документация llama.cpp](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md).

```sh
llama-server -m /path/to/model.gguf --alias chess-tutor --host 127.0.0.1 --port 8080
```

```dotenv
CHESSBRICS_LLM_URL=http://127.0.0.1:8080/v1/chat/completions
CHESSBRICS_LLM_MODEL=chess-tutor
```

При запуске ChessBRICS в контейнере укажите адрес llama.cpp, доступный из контейнера. Например, в Docker Desktop можно использовать `host.docker.internal`, если llama.cpp слушает интерфейс, доступный из Docker.

В разделе «Разбор и задачи» или после завершения партии нажмите «Предложить ход», затем «Объяснить ход». Сервер проверяет ход и передаёт модели позицию, правила, результат хода и примеры допустимых ответов. Наставник объясняет выбранный ход на русском. Запрос наставника может занять до 30 секунд и учитывается в общем лимите LLM.

Тест сервера использует локальный имитатор Chat Completions и проверяет допустимый ответ, резервный ход после ошибочного ответа и изоляцию API-ключа. Для классических правил используется локальная копия chess.js 1.4.0, лицензия BSD-2-Clause включена рядом с библиотекой.

[Промпты для игровых звуков и музыки](AUDIO-PROMPTS.md).

## Аккаунты, рейтинг и турниры

Гостевые партии доступны без регистрации. Аккаунт нужен для автоподбора и участия в турнирах. При регистрации выдаётся одноразовый код восстановления. Сохраните его сразу. Восстановление меняет пароль, отзывает существующие сессии и выдаёт новый код. Аккаунты хранятся в `accounts.json` в том же постоянном томе, что партии. При доступе через интернет используйте HTTPS и передавайте `X-Forwarded-Proto: https` от обратного прокси, чтобы сессионная cookie получила атрибут Secure.

Аккаунт возвращает своё место с другого устройства после входа. В профиле видны онлайн-партии и статистика. Публичность профиля и отображение в рейтинге включаются вручную. Имя, указанное на момент входа в комнату или турнир, видно участникам этой комнаты или турнира.

Автоподбор использует одинаковый вариант и контроль времени, диапазон Elo расширяется после 30 секунд ожидания. Незавершённая заявка удаляется при очередном запросе подбора спустя 10 минут. Базовый рейтинг — 1500, коэффициент — 24. Для БРИКС используется средний рейтинг каждой команды. Гостевые партии, боты, турнирные игры и результаты до двух полуходов не влияют на рейтинг.

Турниры доступны для классики на 4 или 8 человек и начинаются после заполнения сетки. Победитель партии переходит дальше, при ничьей назначается переигровка со сменой цвета. Если три партии в паре завершились вничью, проходят чёрные третьей партии. Турнирные партии и их результаты сохраняются вместе с остальными комнатами.

## Разбор и настройки

В разделе «Разбор и задачи» можно открыть классический PGN, FEN или позицию БРИКС из JSON. В JSON из скачанной партии БРИКС для разбора загружается сохранённая позиция. Подсказки доступны при разборе и после окончания партии. Встроены три задачи на мат в один. Через кнопку с шестерёнкой можно изменить тему, скрыть координаты и включить игровые эффекты и фоновую музыку. Настройки хранятся в браузере. В разделе «Аудио» громкость эффектов и музыки регулируется отдельно. Оба канала выключены по умолчанию, а музыка начинает играть после действия пользователя. В игровом зале и партии по очереди звучат разные пары треков. При переходе на другую вкладку музыка ставится на паузу. Все MP3 из папки проекта public/audio входят в Docker-образ.

### Перебор позиций БРИКС

```sh
npm run solve -- --depth 3
npm run solve -- position.json --depth 4 --nodes 200000
npm run solve -- position.json --exact --nodes 25000
npm run solve -- --record --depth 4
npm run solve -- --arrangements
npm run solve -- --arrangements --variant brics-duel --pieces 3 --positions 5000 --depth 1
```

По умолчанию используется начальная позиция БРИКС 1×1. Можно передать скачанный JSON или объект с полями `variant` (`brics` или `brics-duel`), `turn` (номер цвета) и `board` (100 клеток от a1 до j10 построчно). Клетка хранит `null` или объект с полями `color`, `type` (`prnbqkx`) и `moved` (логическое значение). Путь `-` читает JSON из stdin. Для позиции после взятия короля используйте предыдущий ход.

Обычный режим возвращает ход по последней завершённой глубине поиска и число посещённых узлов. На границе глубины используется оценка материала и расположения фигур. Режим `--exact` строит граф всех достижимых продолжений из заданной позиции. После полного обхода он доказывает выигрыш, проигрыш или ничью без учёта часов. Бесконечное продолжение оценивается как ничья в решателе. Правило ничьей в самой партии от этого не меняется. При достижении лимита выводится `complete: false`, код выхода 2. Полный расчёт стартовой позиции практически недостижим, поэтому точный режим предназначен для небольших эндшпилей.

`--record` обходит все ветви до выбранной глубины из обеих стартовых позиций и обновляет дебютную книгу бота. `--arrangements` без дополнительных параметров рассчитывает точную таблицу для двух королей в обоих режимах и обновляет таблицу бота.

Для произвольных расстановок задайте `--pieces` от 3 до 40 и число позиций за запуск через `--positions`. Перебор учитывает клетки, цвета, типы фигур, очередь хода и признаки первого хода. Он проверяет ограничения расстановки, включая количество фигур каждого цвета, и может включать позиции, недостижимые из начальной расстановки. Для продолжения используйте значение `nextSkip` из `report.json` в параметре `--skip`, сохранив остальные параметры. Можно выделить часть пространства параметром `--kings e1,e10`, где первая клетка относится к красному королю. Для расчёта с большим числом фигур используется заданная глубина. Полный перебор для всех составов не выполнялся.

Каждый запуск создаёт отдельный каталог в `data/search` или в пути из `--output`. В архивах `.gz` сохранены все переходы в границах прогона. В дебютном журнале первая строка задаёт начальную позицию и схему столбцов. Строки ходов идут от потомков к родителям, поэтому `parent` может ссылаться на строку ниже. Корневой узел имеет ID 0. Оценка записана со стороны игрока, который сделал ход. В точной таблице каждая строка позиции содержит список `edges` со ссылками на ID следующих позиций. `next: null` обозначает взятие короля. В журналах более крупных расстановок переходы записаны как JSON-массивы в порядке столбцов `treeColumns`. Они относятся к последней записанной позиции, а после них идёт сводка с кандидатом.
